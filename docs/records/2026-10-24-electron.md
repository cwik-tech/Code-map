# Record: Electron support, 2026-10-24

## Why this record exists

On 2026-10-22 the user deferred Electron, Python and React Native. On 2026-10-23 the user asked to implement everything that Electron needs. This record says what was built, how two real Electron apps checked it, which defects those apps found, and what stays unproven. The design with its approved decisions is [the Electron design](../work/2026-10-24-electron/design.md). The guide is [docs/electron.md](../electron.md).

The apps are private projects of the user. This record names them as in [the real-codebase record](2026-10-23-real-codebase-validation.md): Project B (React, Electron 33, Vitest) and Project C (React, Electron 39, ES modules).

## What was built

| Part | What Code-map does | Plan reference |
| --- | --- | --- |
| IPC contracts | Finds the IPC calls of the main process, the preload and the renderer. Follows channels through wrappers, also through injected dependencies, up to three levels. Gives four findings: no handler, kind mismatch, no listener, unused handler | C26 |
| Window security | Reads the `webPreferences` of each window with Electron's version defaults. Gives a high finding for an unsafe value, and low leads for a missing permission handler and for `shell.openExternal` with a non-literal URL | C26, stack table |
| Entry points | Resolves the `main` field and each preload path to their source files through the TypeScript output settings. Supports `path.join`, a named `join`, and the ES-module form `fileURLToPath(new URL(…, import.meta.url))` | Stack table: packaging |
| Platform code | Lists the platforms of each file's `process.platform` checks. `verify` reports the platforms that a change touches | Stack table: OS-specific behavior |
| Startup and memory | A probe for the person's own run writes a self-attested `electron-startup` report. `verify` compares base and head with the statistics of the controlled timings | C36 |

No rule set changed: the findings get NEW, EXISTING and RESOLVED labels like all findings. A project without `electron` in its `package.json` gets no Electron block.

## How the real apps checked it

Three Codex sessions built the parts in parallel. Each new behavior got a test that failed without it. The combined work passed the full suite. Then it ran read-only on the two apps. `git status`, also of ignored files, was the same before and after each run.

| Run | Project B | Project C |
| --- | --- | --- |
| First run | 127 channels, 7 wrappers, 40 handlers found, 88 false high "no handler" findings. Main entry found, preload "dynamic" | Not run yet |
| After the injection fix | 127 channels, 128 handlers, 136 callers, 0 IPC findings. Main and preload resolved | 60 channels, 60 handlers, 61 callers, 0 IPC findings. Preload "dynamic" |
| After the ES-module fix | Unchanged | Main and preload resolved |

The defects that the apps found:

1. **Injected wrappers.** Project B passes its IPC wrapper to the handler modules in a `deps` object, so that tests can call the handlers. Code-map followed only direct function names, and 88 of 127 channels looked unhandled. Code-map now follows a wrapper from the call site that passes it into a function, through object properties and destructuring. It never matches a property by its name alone.
2. **A named `join` import.** Project B writes `join(__dirname, "preload.cjs")` with `join` imported from `node:path`.
3. **The ES-module preload form.** Project C writes `fileURLToPath(new URL("./preload.js", import.meta.url))`.

The fixture tests of the first build passed while defect 1 made the main check unusable on a real app. A real codebase is necessary before such a check counts as effective.

The security checks on Project C gave three findings:

- `sandbox: false`: a correct detection. The app sets it explicitly. An ES-module preload needs it, so a person judges the trade-off.
- No permission handler: correct.
- `shell.openExternal` with a non-literal URL: a false alarm in substance. The app validates the URL first. Code-map cannot see the validation. The guide documents this limit, and a person can dismiss the lead with `code-map triage`.

## What stays unproven

- The startup probe ran only in unit tests with a simulated Electron. It has not run with a real app, because that opens a window on the user's screen. The user can run it with `code-map electron-probe`, which prints the command.
- Two apps are a small sample. Other IPC styles, such as a channel registry that a loop registers, can need more support.
- Python and React Native stay deferred.
